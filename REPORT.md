# Звіт з лабораторної роботи № 2
**Тема:** Класи, record і інкапсуляція в Java-проєкті.
**Варіант:** 5 (Меню кафе).

## 2. Мета роботи
Перебудувати предметну частину продукту з лабораторної роботи № 1: замість сирих рядків і масивів використати власні класи, додати перевірку стану об'єктів, record для підсумкових значень та тести для підтвердження збереження поведінки програми.

## 3. Стан до і після цієї роботи
* **До:** Дані оброблялися безпосередньо у класі `Main` у циклі `while`. Перевірки були розкидані по коду, а статистика накопичувалася у локальних змінних.
* **Після:** Створено архітектуру MVC (без View). Дані капсулюються у класі `MenuItem`, звіт формується у вигляді `MenuSummary`, а керує процесом `MenuController`. Клас `Main` тепер виконує лише функцію точки входу.

## 4. Клас-сутність
Створено клас `MenuItem` з інкапсульованим станом:
* Усі поля мають модифікатори `private final`.
* Конструктор містить інваріанти: відхиляє `null`, порожні рядки (постачальник, назва, категорія) та від'ємні числа (ціна, вага, час).
* Відсутність методів-сеттерів гарантує повну незмінність (immutability) об'єкта після його створення.

## 5. Фабричний метод і record
* **Фабричний метод:** Реалізовано метод `MenuItem.fromCsv(String line)`, який бере на себе відповідальність за парсинг рядка (розбиття через `split`, обрізку пробілів `trim`, перетворення типів) та створення об'єкта.
* **Record:** Для фіксації результатів роботи створено `MenuSummary(int count, double averagePrice, int highestWeight, int longestPrepTime)`. У його компактному конструкторі додано захист від від'ємних значень.

## 6. Тестування
Створено новий тестовий клас `MenuItemTest`. Використано анотації `@Test` та методи `assertEquals`, `assertThrows`. Покрито такі сценарії:
* Успішне створення об'єкта з коректного рядка.
* Викидання `IllegalArgumentException` при передачі порожніх рядків, від'ємної ціни або некоректних числових форматів.
Усі старі тести з `MainTest` збережено і вони успішно проходять.
