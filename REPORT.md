# Звіт до лабораторної роботи № 1

## 1. Тема, номер і варіант
**Предметна область:** Меню кафе.
**Номер варіанта:** 5.
**Операційна система:** Windows 11 (розробка), Ubuntu/macOS/Windows (CI).

## 2. Мета роботи
Пройти повний шлях від створення репозиторію й налаштування інфраструктури до версії простої консольної програми, яку можна відтворено зібрати й запустити на Windows, macOS та Ubuntu.

## 3. Постановка задачі
Створити консольну програму для обробки меню кафе. 
Формат запису: `supplier:String; name:String; category:String; price:double; weightG:int; prepMin:int`.
Програма має обчислювати 4 показники: кількість коректних записів, середня ціна, найбільша вага, найдовший час приготування.

## 4. Структура програми
* `data/input.csv` — вхідні дані для тестування.
* `src/main/java/ua/lpnu/kzp/Main.java` — головний клас, що виконує читання, валідацію полів, обчислення та збереження звіту.
* `src/test/java/ua/lpnu/kzp/MainTest.java` — клас із модульними тестами (JUnit 5).
* `out/report.txt` — згенерований файл зі звітом.

## 5. Інфраструктура
* **Maven:** використано для управління залежностями та збірки (наявний `pom.xml` та `mvnw`).
* **Залежності:** JUnit 5 (`junit-jupiter`) для тестування.
* **Аналізатор:** SpotBugs прив'язаний до фази `verify`.
* **Пакування:** `maven-shade-plugin` створює виконуваний JAR-файл.
* **CI/CD:** Налаштовано GitHub Actions (матриця для 3 ОС: `ubuntu-latest`, `windows-latest`, `macos-latest`), який публікує JAR як артефакт.

## 11. Відповіді на контрольні питання
1. Яке призначення файла pom.xml?<br>
   - Це файл проєкту Maven. Він містить різну інформацію: опис проєкту, бібліотеки та налаштування плагінів для збірки.
3. Чим відрізняються фази test, verify і package у Maven?<br>
   - test виконує модульні тести, verify відповідає за додаткові перевірки, а package компілює та пакує код у JAR-файл.
5. Навіщо потрібен Maven Wrapper?<br>
   - Дає змогу збирати проєкт без попереднього встановлення Maven. Гарант використання одної версії інструменту локально та на серверах. 
7. Яку роль відіграє метод main?<br>
   - Початок виконання Java-програми.
9. Чим примітивний тип відрізняється від String?<br>
   - Примітивні типи зберігають значення, не маючи методів. String відноситься до посилального типу, що містить масив символів та набір методів для роботи з текстом.
11. Чому середнє потрібно обчислювати в double, навіть якщо сума й кількість мають тип int?<br>
    - Ділення двох цілих чисел (int) у Java відкидає дробову частину (наприклад, 5 / 2 = 2). Використання double зберігає точність (5.0 / 2 = 2.5).
13. Що станеться, якщо Integer.parseInt отримати рядок "abc"?<br>
    - Програма викине виняток NumberFormatException, оскільки ці літери неможливо перетворити на число.
14. Чому не можна мовчки пропускати рядок із помилкою?<br>
    - Це призведе до прихованої втрати даних або неправильних розрахунків. Користувач повинен бачити, які саме рядки були відхилені та з якої причини.
15. Як String.split(";", -1) обробляє порожнє останнє поле?<br>
    - Параметр -1 гарантує, що порожні значення в кінці рядка збережуться як порожні елементи масиву (без нього метод split за замовчуванням ігнорує порожні елементи в кінці).
16. Чому для шляхів краще використовувати Path.of, а не "data\\\\input.csv"?<br>
    - Path.of автоматично адаптує розділювачі директорій під поточну операційну систему (\ для Windows, / для Linux/macOS), забезпечуючи кросплатформність.
17. Навіщо явно задавати StandardCharsets.UTF_8?<br>
    - Щоб українські літери коректно зчитувались та записувались.
18. Чим %n відрізняється від \n у форматованому виводі?<br>
    - %n підставляє правильний символ переходу на новий рядок для конкретної ОС (наприклад, \r\n для Windows), тоді як \n — це жорстко заданий перехід тільки для Unix-подібних систем.
19. Які дані потрібно перевірити у вашому варіанті?<br>
    - У варіанті "Меню кафе" потрібно перевіряти наявність текстових полів (постачальник, назва, категорія), а також правильний формат і додатність числових значень (ціна, вага, час приготування).
20. Які тести виявлять помилку в обчисленні середнього?<br>
    - Тести, де сума не ділиться націло (перевірка плаваючої коми), та тести з нульовою кількістю коректних записів (щоб уникнути ділення на нуль).
21. Яке призначення статичного аналізатора?<br>
    - Він перевіряє код без його запуску, знаходячи потенційні баги, вразливості або погані практики (як у випадку з нашим NullPointerException).
22. Яку роль виконує GitHub Actions?<br>
    - Він автоматизує процес CI/CD: автоматично збирає проєкт, запускає тести та аналізатори на різних ОС (Windows, Ubuntu, macOS) під час кожного пушу.
23. Що має містити GitHub Issue на дефект?<br>
    - Короткий опис проблеми, кроки для її відтворення, очікувану поведінку та фактичний результат (бажано з логами або скріншотами).
24. Що Ви повинні вказати у розділі звіту про академічну доброчесність?<br>
    - Які саме ШІ-інструменти використовувалися (наприклад, Gemini), для яких завдань (ролі Менеджера, DevOps, Валідатора) та підтвердження власної відповідальності за код.
25. Яку роботу виконує агент DevOps, а яку – агент Валідатор?<br>
    - Агент DevOps допомагає з конфігурацією інфраструктури (налаштування Maven, створення ci.yml). Агент Валідатор допомагає шукати помилки в коді та виправляти зауваження від статичних аналізаторів.
26. Який рядок вашої програми найскладніше пояснити і чому?<br>
    - Блок з Files.createDirectories(parent). Довелося пояснювати SpotBugs, що ми не розіменовуємо null, явно зберігши результат outputPath.getParent() в окрему змінну перед перевіркою, щоб обійти попередження аналізатора.

Налаштовано повну кросплатформну інфраструктуру (Maven, SpotBugs, JUnit 5, GitHub Actions), що відповідає вимогам Рівня 3.
